> **Full notes:** [[notes/Linux/anatomy-of-a-userspace-hang|Anatomy of a Userspace Hang -->]]

**The one-line mechanism:** a linked-list node was freed while still linked, `free()` left its `next` pointer intact so nothing broke, the chunk was later reallocated as a node in a *different* healthy circular list, and a once-per-second walk from the original owner's head now goes round a ring that does not contain that head. One core, forever, zero errors, zero restarts.

## Key Concepts

### Processes, threads, containers
- Linux has **one** kernel object: the task. `clone()` with sharing flags makes a thread, without makes a process.
- **TGID** = userspace PID. **TID** = per-thread id. `/proc/<TGID>/task/<TID>/`.
- The scheduler schedules **threads**. "The process is at 100%" is never the useful statement.
- A container = process tree + namespaces (what it sees) + cgroups (what it uses) + rootfs.
- **PID namespace**: the workload is always `/proc/1` inside its own container.
- `comm` is **16 bytes incl. NUL**, so thread names truncate at 15 chars (`flb-out-stackdr`).
- Threads observed: `flb-pipeline` (the engine), 2x `flb-out-stackdr` (output workers), `monkey` (HTTP server), `flb-logger`, plus main.
- The HTTP server is a **different thread** from the engine. That is why probes passed for 3 months.

### utime / stime: the 3-second decisive test
- Ring 3 (user) vs ring 0 (kernel); the boundary is the `syscall` instruction.
- `/proc/<tid>/stat` fields **14 = utime, 15 = stime**, in **100 Hz ticks** (`getconf CLK_TCK`). Counters: sample twice, diff.
- `cores = delta_ticks / (100 * seconds)`
- **Observed: +313 utime, +1 stime over 3 s** = **1.04 cores of pure userspace**, 0.3% kernel.
- That one ratio killed every syscall-spin theory, including the famous `EAGAIN` TLS retry spin (~8,500 `read()`/s, which would be `stime`-heavy).

```
 high utime, ~0 stime   -> userspace infinite loop
 high stime             -> syscall spin or real I/O
 both ~0                -> not running: deadlock, or D-state
```

### Thread states and wchan
| State | Meaning | Note |
|---|---|---|
| `R` | running/runnable | "R" does not mean healthy |
| `S` | interruptible sleep | normal idling |
| `D` | uninterruptible sleep | kernel/IO; **unkillable**, fix the device |
| `Z` | zombie | parent bug |
| `T` | stopped | SIGSTOP or debugger |

- `wchan` = the kernel function a sleeping task is parked in.
- `do_epoll_wait` = **idle event loop, healthy**. `hrtimer_nanosleep` = deliberate sleep. `futex_wait` = **waiting on another thread** (where deadlocks live).
- Idle-waiting != blocked-on-lock != spinning.

```
 DEADLOCK       a WAITING failure.     >=1 thread, futex_wait, CPU ~0. permanent.
 INFINITE LOOP  a COMPUTING failure.   1 thread, R, 1 core utime, ~0 stime.
 LIVELOCK       a COORDINATING failure. burns CPU *and* makes syscalls. looks busy.
```

- **Observed:** thread 14 `R`, wchan empty; both output workers `S` in `do_epoll_wait` (idle, not blocked). Deadlock ruled out.
- **Unexamined variant:** 23 of the 101 broken nodes sat at **exactly 0 m CPU**, still `1/1 Ready`. Deadlock signature. Still open.

### /proc
- A **pseudo-filesystem**: content is generated by a kernel function *at read time*. Size reports 0. Sampling is nearly free.
- `stat` parsing trap: field 2 is `comm` in parens and may contain spaces/parens. **Cut at the last `)`**, then state=1, utime=12, stime=13.
  ```sh
  sed 's/.*) //' /proc/1/stat | awk '{print $1, $12, $13}'
  ```
- `syscall` -> `"running"` when in userspace. `maps` -> where the binary landed. `task/` -> threads. `stack` -> kernel stack only.
- **`kstkeip` (field 30) reads 0** on modern kernels even privileged: gated behind `PTRACE_MODE_ATTACH_FSCREDS`, and a thread running on another CPU has no saved user register frame. **This is why ptrace was required.**

### Event loops, epoll, coroutines
- `epoll_create1` / `epoll_ctl` / `epoll_wait`. One thread, many fds. `epoll_wait` is the *only* place a healthy loop sleeps.
- **Cooperative**: nothing preempts a callback. A callback that never returns freezes every fd on that loop.
- **Timers are just fds** (`timerfd`), so periodic work shares the fate of every other callback.
- Level-triggered reports an fd ready while the *condition holds*; `EAGAIN` + no state change = full-speed spin with no error. Edge-triggered reports only on *change*.
- **Coroutines** = user-level context switch (~20 instructions, no kernel), yielding only at explicit points, normally where I/O would block. Pure computation has **no yield point**.

The engine thread carried all of this on one loop: input collectors, **all filters**, flush scheduling, the retry scheduler, and the 1-second metrics timer.

```
 engine loop stops returning
  -> tail timer never fires        -> every pod on the node stops shipping, at once
  -> flushes never scheduled       -> output workers idle in epoll_wait, LOOK healthy
  -> retry timers never fire       -> "retry in 7 seconds" never happens
  -> metrics timer never fires     -> all plugin counters FREEZE
  -> nothing produces log lines    -> silence (the logger thread is fine, just empty)

 different thread:
  -> :2020 keeps answering; uptime = now - init_time, computed per request, CLIMBS
  -> /api/v1/metrics returns the last snapshot the engine pushed, FROZEN
```

**Uptime climbing while record counters sit still** is structural, not coincidence. Cheapest remote fingerprint.

### Memory: what free() actually does
- Stack: automatic, per-thread, lifetime = the call. Heap: manual, `malloc`/`free`, lifetime = your decision.
- A **pointer is just a 64-bit integer**. Everything follows from that.
- **`free()` does not erase bytes, unmap pages, or tell the kernel anything.** It marks the chunk available.
- glibc **tcache** (per-thread, 64 size classes, 7 chunks each) and **fastbins** store link pointers *inside the freed chunk*, overwriting only the **first 16 bytes** (`next`, then the double-free `key`). Bytes 16+ survive verbatim.
- Reuse is **LIFO**: the next same-size `malloc` very often returns the chunk you just freed. Not "eventually and at random".

```
 t0  node = malloc(24); node->next = X
 t1  free(node)                    16 bytes clobbered, rest preserved. NO SYMPTOM
 t2  read node->next -> still X    valid address, mapped page. NO SYMPTOM
 t3  other = malloc(24)            same chunk handed back
 t4  other->next = Y               legitimate write
 t5  read node->next -> Y          SYMPTOM, at last. t1..t3 gap = weeks.
```

- **Dangling pointer** = address outlived the object. **Use-after-free** = dereferencing it (UB). **Double free** = same chunk on the list twice, two owners get one address.
- **"Corruption" != scribble.** The dangerous form is a **violated invariant via a stale reference**: every byte valid, every pointer real, and the *graph* wrong.

| Scribble | Stale reference |
|---|---|
| bytes are garbage | every byte is a valid value |
| pointers point at nonsense | every pointer targets a real object |
| obvious in a dump | invisible in a dump |
| crashes fast | can hang, or work for months |

### Intrusive circular doubly linked lists
- **Intrusive**: the link struct is embedded *inside* the payload (kernel `list_head`, `cfl_list`, `mk_list`). Zero allocations for membership; `container_of` gets back to the owner. Note the stored addresses are **field addresses, not object addresses**.
- **Circular, head is a sentinel embedded in the owner.** Empty list: `head.next == head.prev == &head`. This removes every special case and makes `list_del` branch-free.
- The walk is always `for (it = head->next; it != head; it = it->next)`.
- **The only terminator is identity with the head.** No NULL, no length field, no bounds check, no iteration cap.

```
 stale next -> unmapped address     -> dereference faults  -> SIGSEGV   (crash)
 stale next -> a valid ring that
               excludes the head    -> walk never ends     -> INFINITE LOOP (hang)
```

**Same defect, two symptoms, decided by heap-layout luck.** That is why the fleet had ~2,300 segfaults/day *and* 78 permanently spinning pods.

```c
static inline int cfl_list_size(struct cfl_list *head)
{
    int ret = 0;
    struct cfl_list *it;
    for (it = head->next; it != head; it = it->next) {
        ret++;
    }
    return ret;
}
```

```asm
  +0x25    add    $0x1,%eax          ; ret++              <-- 50 of 60 samples
  ...
  +0x35    mov    0x8(%rdx),%rdx     ; it = it->next      <-- 10 of 60 samples
  +0x39    cmp    %rdi,%rdx          ; it == head ?
  +0x3c    jne    <+0x25>            ; no -> go round again
```

Seven instructions, **no calls, no syscalls**, fits in L1. Invisible to `strace` (empty `-c` table). Runs at exactly 1.00 core.

### cmetrics and the CORRECTED mechanism
- A counter is **one number**. Labels split it: `requests_total{status,name}` is one family, many instances.
- `cmt_map` holds `label_keys`; each `cmt_metric` holds a list of **label VALUES**:
  ```c
  struct cmt_map_label { cfl_sds_t name; struct cfl_list _head; };  /* _head at +8 */
  ```
- A never-seen label combination **allocates a new metric and new label nodes at runtime**.
- Once a second: `flb_engine_start -> flb_me_fd_event -> collect_metrics -> flb_me_get_cmetrics -> cmt_cat -> append_context -> copy_counter -> copy_map -> copy_label_values -> cfl_list_size()`. **Every metric's label list, walked in full, every second.** A corruption **detector** nobody designed as one.
- **`"403"` is a legitimate label value.** The plugin declares `requests_total{status,name}` and fills `status` from `snprintf` of the HTTP status.

The corrected sequence:
1. A label node of metric **M** was **freed while still linked**. Free site **not pinned down**; candidates are the OAuth/metadata parser dangling pointers, or the metrics library's map/cat lifecycle.
2. `free()` left the `next` pointer intact, so M's walks still terminated. **Weeks of zero symptoms.**
3. The **first 403** created `requests_total{status="403",...}`; same size class + LIFO reuse handed that exact chunk back as one of its label nodes.
4. Two owners, one node:

```
 the 403 metric's list is PERFECTLY HEALTHY:
     B (head, in the 403 cmt_metric) -> C ("403") -> A ("out.0") -> B      terminates

 the stuck metric M's head was never updated:
     M.head (0x...247358) --next--> A
     walk: A -> B -> C -> A -> B -> C -> ...   M.head is OUTSIDE the ring
     `it != M.head` is true forever
```

5. One second later the metrics timer fires, `cfl_list_size` enters the loop, and the engine never returns to `epoll_wait`.

**RETRACTED: "error handling wrote 403 over the list".** Wrong on two counts. The `403` is a real label value (feature mistaken for wreckage), and the nearby `logging.googleapis.com` was **heap-neighbour noise** from strings the error path allocated at the same time. Adjacency in a dump is never causation. What settled it: every pointer in the ring was **well-formed, aligned, and mutually consistent with valid `prev` links**. Well-formed structures encoding a wrong graph = **reuse**, not overwriting.
**Fix category changes with it:** not bounds-checking an error path, but **lifetime ownership** (unlink before free) plus the upstream lifecycle fixes.

### Debugging without a shell
- Distroless = no shell. `kubectl exec -- sh` -> `executable file not found`.
- **Ephemeral containers** (GA 1.25): `kubectl debug -it pod/X --image=busybox --target=<container>`.
- **`--target` is load-bearing.** Without it you get your own PID namespace and `/proc/1` is your own `sleep`, and the output looks plausible. Sanity check: `cat /proc/1/comm`.
- **`--profile=sysadmin`** fixes two independent blocks: `ptrace` on a non-descendant needs **`CAP_SYS_PTRACE`** (dropped by default), *and* the `RuntimeDefault` **seccomp** profile blocks the `ptrace` syscall outright.
- **Yama** `/proc/sys/kernel/yama/ptrace_scope`: `0` classic, `1` ancestors only (common default), `2` admin only, `3` **disabled and cannot be lowered without a reboot**. `CAP_SYS_PTRACE` bypasses 0-2.
- RBAC note: `pods/ephemeralcontainers` is a **separate** permission from `pods/exec`.
- `ptrace` requests: `ATTACH` (async, must `waitpid`) / `GETREGS` / `PEEKDATA` (word is the return value, so clear and check `errno`) / `DETACH`. **Per-thread: attach to the TID, not the PID.** Exclusive: one tracer per thread.
- **60 samples at 50 ms: 50 at `cfl_list_size+0x25`, 10 at `+0x35`, 0 anywhere else.** Sixty of sixty inside an 8-instruction window is a proof, not a profile.
- Call chain without an unwinder: **stack scan** from `RSP`, keep words that fall inside the `r-xp` mapping, treat them as return addresses. Heuristic, but ordered.

### ELF, PIE, symbolisation
- ELF: **program headers** = what the kernel loader maps; **section headers** = what tools read; symbol table = name -> address.
- **PIE** + ASLR means file addresses are offsets, not runtime addresses.

```
 load bias = runtime start of the r-xp mapping - its file offset
           = 0x5cd56a697000 - 0xbf000
           = 0x5cd56a5d8000

 file_addr = RIP - bias
 symbol    = greatest nm -n entry <= file_addr, offset = the difference
```

- Use the **`r-xp`** mapping (not `r--p`/`rw-p`), and do not assume file offset 0.
- Cross-arch: `docker pull --platform linux/amd64` from an arm64 laptop, `docker create` + `docker cp` the binary out. `nm`/`objdump` parse foreign ELF fine because they never execute it. Needs the **exact same image digest**.

### What Kubernetes could see
- Kubernetes restarts on **process exit** or **liveness failure**. That is the whole list.
- `128 + N`: **137** = SIGKILL (OOM/probe kill), **139** = SIGSEGV (memory-safety bug), **143** = SIGTERM overrun, **1/2** = the program chose to exit.
- Ownership: 137 is usually yours (limits, buffers); 139 is usually upstream's (pin, or stop running the faulting component).

| | Crash (139) | Hang |
|---|---|---|
| kubelet action | restarts | **nothing** |
| `restartCount` | increments | **stays 0** |
| visibility | loud, counted | **invisible** |
| self-healing | yes, seconds | **never** |
| data loss | seconds | **hours to months** |

- **The crash is the good outcome.** ~2,300 restarts/day cost seconds each; the hangs cost up to 3.5 months each. The loud symptom was the harmless one, which is a textbook **anchoring trap**.
- **Liveness != progress.** An HTTP probe asks a *different thread* whether that thread is alive. A TCP probe is worse: the listening socket lives in the kernel and stays accept-able with no userspace `accept()`.

> A probe served by a different thread than the work cannot observe the work stopping. Liveness for a pipeline component must assert a **monotonic counter advanced inside a bounded window**.

- Detector scorecard:
  ```
  X  restartCount > 0                 0 on every hung pod
  X  HTTP liveness on :2020           200 for three months
  X  error-rate health endpoint       zero errors: nothing ran, nothing failed
  X  memory limit / OOM               10-200 MiB against a 512 MiB limit
  ~  CPU flat ~1 core, low variance   found 54 of 101; blind to the 0-CPU variant
  OK per-node output rate == 0        found all 101
  ```
  ```promql
  min by (node) (rate(agent_output_records_total[10m])) == 0
  ```
  Pair with `absent_over_time(...)` at equal severity (`== 0` never fires on a missing series), and qualify with "this node has app pods" (13 GPU nodes were correctly idle).
- Recovery is clean because read offsets live in a DB on a **hostPath**, so a new pod resumes at the byte where the old one stopped. But rotation (typically 5 x 10 MiB per container) means a 3-month hang resumes into inodes unlinked in May. **Offsets survive; data does not.**

### Signals and why both stacks match
- SIGSEGV(11) = MMU page fault with no valid mapping. SIGBUS(7) = valid mapping, unusable access. `SIGKILL`/`SIGSTOP` cannot be caught.
- A handler runs **on the faulting thread's stack**, which is what makes a backtrace possible: libbacktrace walks DWARF (`.eh_frame`) for a *real* unwind, then re-raises so the process exits 139.
- Sharp edge: handlers must be **async-signal-safe**; `malloc`/`printf`/backtrace libs are not. Fault inside the allocator while it holds its lock and the handler deadlocks, so **a crash can present as a hang**.
- The daily crash stack and the ptrace'd hang chain are **identical**, frame for frame, from `cfl_list_size` down to `flb_engine_start`. One bug:

```
              a label node is freed while still linked
                            |
        +-------------------+-------------------+
        v                                       v
  chunk reused leaving garbage at +8      chunk reused as a valid node
                                          in a DIFFERENT healthy ring
        v                                       v
     SIGSEGV                              INFINITE LOOP
  exit 139, restart, ~5 s lost       3 months of total loss on that node
  LOUD, COUNTED, SELF-HEALING        SILENT, UNCOUNTED, PERMANENT
```

**The crash rate is a leading indicator of hang risk**, not cosmetic noise.

## Quick Reference

### The 3-command triage

```sh
# 1. thread inventory + CPU split + states. run twice, 3 s apart, and diff.
for t in /proc/1/task/*; do
  printf '%-6s %-16s %-24s %s\n' "${t##*/}" "$(cat $t/comm)" \
    "$(sed 's/.*) //' $t/stat | awk '{print $1, $12, $13}')" \
    "$(cat $t/wchan 2>/dev/null)"
done

# 2. userspace or syscalls?
timeout 5 strace -f -p 1 -c          # empty table = zero syscalls = userspace loop

# 3. where in userspace?  (needs --profile=sysadmin)
python3 sample.py <tid> | sort | uniq -c | sort -rn
```

### Decision tree

```
 pod Running, restartCount 0, shipping nothing
   |
   +- sample utime/stime twice
        |
        +- utime ~100 ticks/s, stime ~0 -----> USERSPACE INFINITE LOOP
        |    ptrace-sample RIP -> symbolise via load bias + nm -n
        |    -> walk the structure by PEEKDATA -> ring without its head
        |
        +- stime high, many syscalls --------> SYSCALL SPIN
        |    strace -c: floods of EAGAIN = level-triggered retry spin
        |    ss -tinp: ESTABLISHED, empty rx queue, lastrcv in days
        |    fix: set a finite net io timeout
        |
        +- both flat at 0, all S/futex_wait -> DEADLOCK (the unexamined variant)
        |
        +- both flat at 0, any thread D -----> stuck in the kernel; check the device
```

### Log signature

```
 unable to parse token body
 cannot retrieve oauth2 token
 {"error":{"code":403,"status":"PERMISSION_DENIED"}}
 <!DOCTYPE html> 400 Bad Request     (corrupted request line)
 <!DOCTYPE html> 404 Not Found       (corrupted request path)
 [warn] failed to flush chunk ... retry in 7 seconds
 (silence, forever -- and the retry never happens)
```

The tell is the last line: a promise to retry, then permanent silence, means the thread owning the retry timer stopped.

### Metrics signature

